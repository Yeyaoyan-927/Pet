# 宠物造型与高端养护门店作业台

面向宠物造型与高端养护门店的**内部作业台**。把客户从到店评估、造型方案、排期派工、施工推进、质检交付到会员养护周期的全链路搬到线上，替代纸质档案与 Excel 排期。

服务对象只有两类角色：**美容师**（接客、评估、施工、质检、领料）与**店长**（美容师全部权限 + 排期调配、耗材采购、会员规则、经营分析）。

> AI 只负责听懂和调度，不负责执行。所有写操作（开单、改期、改价、扣库存、会员变更）必须经用户确认，再走业务层完成权限校验、状态流转、事务与审计。

## 核心设计

### 1. 多 Agent 编排（8 个）

| # | Agent | 职责 |
|---|---|---|
| 1 | 路由调度 | 判断这一轮由谁回应：规则优先、模型纠偏、越权退回规则 |
| 2 | 造型方案 | 按品种 / 脸型 / 毛量 / 预算出 2–3 个方案，带工期、报价、风险 |
| 3 | 洗护与保养 | 洗护频次、护毛搭配、SPA 与皮肤护理、产品选择 |
| 4 | 赛级养护 | 毛量维护、包毛节奏、赛前状态，按周出计划 |
| 5 | 施工与质检 | 步骤拆解推进、成品比对、返修判断 |
| 6 | 排期与派工 | 美容师 + 工位 + 设备三资源排期，技能等级匹配 |
| 7 | 耗材与库存 | 用量预估、领用、盘点、补货申请 |
| 8 | 会员与经营 | 会员权益、周期提醒、复购预测、产能与毛利 |

- 8 个 Agent 共用**同一个执行内核 + 工具注册表**，差别只在领域提示词与工具子集
- 工具池 28 个，其中 13 个写操作全部进入确认闸门
- 两角色按工具白名单收敛：美容师可激活 6 个、店长 8 个
- **合规校验不是第 9 个 Agent**：它不调模型，是回答出口的规则闸门，保证每次判定一致

### 2. 三路知识协同

造型场景的知识不止一种形态，全塞进向量库会互相污染：

| 知识类型 | 存储 | 回答什么问题 |
|---|---|---|
| 结构化关系 | **Neo4j** | 这个条件下**能不能做**：能做哪些造型、缺什么工具、有无禁忌 |
| 案例图 | **COS + Chroma（图文配对）** | **长什么样**：相似成品图 + 施工步骤 + 出处 |
| 规范文本 | **Chroma** | **怎么做、为什么**：犬种标准、产品用法、养护频次 |

- 图谱约 1800 节点 / 4200 关系，走图判断比多表 JOIN 更易维护，也支持多跳推理（品种 → 造型 → 工具 → 替代品）
- 图库按「图 + 结构化描述（脸型 / 毛质 / 耳型 / 留毛长度）+ 步骤」存，检索命中描述即返回图与出处；纯文本检索在造型场景没有价值
- **先按品种过滤再检索**：品种识别结果直接作为分片过滤键，不跨品种检索，比调相似度阈值有效

### 3. MCP 接入（3 个外部服务）

| 服务 | 输出 | 用途 |
|---|---|---|
| 品种识别 | 品种 + 置信度 | 决定用哪套标准与模板；混血退到体型 + 毛质匹配 |
| 毛质皮肤分析 | 打结度、红斑、皮屑、毛量评分 | 「做不做得成」的判据，毛量不足直接不给赛级方案 |
| 体尺估算 | 体长 / 体重区间 | 报价与耗材预估 |

- 传输：streamable-http + JSON-RPC，启动时 `tools/list` 发现能力并缓存 schema
- 不同服务商的协议差异由**适配器层**隔离
- 超时 15s、失败重试 1 次、连续失败熔断降级；不可用时回退人工选择，主流程不中断
- **MCP 能力不进模型工具池**，只由 Skill 调用——接入再多服务，模型能选的工具数不变

### 4. Skill 编排（6 个）

| Skill | 做的事 |
|---|---|
| 到店评估与造型方案 | 拍照 → 品种识别 → 毛质评估 → 拉档案 → 匹配模板 → 出方案草稿（不落库） |
| 洗护保养方案 | 按毛质皮肤定洗护频次、产品搭配、SPA 项目，出周期表 |
| 赛级养护计划 | 按毛型排周计划 → 打卡 → 毛量趋势 → 到期提醒 |
| 施工分步指导 | 拆步骤，每步给工具、要点、目标耗时；逐步确认，异常可中断重评 |
| 质检与交付 | 成品拍照比对模板 → 差异点与返修建议 → 交付单 + 在家打理建议 |
| 耗材与会员联动 | 领料扣库存、回写单均成本；会员到期按毛型周期提醒 |

Skill 只产出结构化参数，不直接写库。

## 架构分层

```
routers（接口层）  →  services（业务编排）  →  rules（纯规则）  →  models（数据模型）
                          ↑
    agent（多 Agent 内核 / 工具 / MCP 客户端）  →  services
    rag（检索管线）                          →  services
    tasks（定时任务）                        →  services
    config / constants / deps / utils        ← 被所有层依赖
```

- `rules/` 不 import 框架，保证可单测
- 规则（可行性判定、合规红线、定价、状态机）全部集中在此
- `agent/` 是 LLM 访问业务的唯一通道，业务模块不得反向 import

## 快速开始

```bash
# 1) 依赖
python -m venv .venv
.venv\Scripts\activate
pip install -r backend/requirements.txt

# 2) 配置
cp backend/.env.example backend/.env
# 填 MySQL / Neo4j / COS / DASHSCOPE_API_KEY（不填 Key 自动降级为规则引擎，业务不中断）

# 3) 建库
mysql -h127.0.0.1 -uroot -p -e "CREATE DATABASE IF NOT EXISTS pet_groom DEFAULT CHARACTER SET utf8mb4;"
python backend/scripts/init_db.py

# 4) 图谱初始化（可选，未装 Neo4j 时自动降级为关系表查询）
python backend/scripts/init_graph.py

# 5) 启动
cd backend && python -m uvicorn app.main:app --port 8000
```

前端：

```bash
cd frontend
npm install
npm run dev      # http://127.0.0.1:5173
```

## 质量保障

```bash
cd backend
pytest                                    # 单元测试，服务层覆盖率门槛 80%
python scripts/smoke.py                   # 接口冒烟，覆盖两角色主链路
node ../frontend/scripts/verify-spa.mjs   # 浏览器端到端
```

- 覆盖：造型方案、排期冲突、施工推进、质检返修、会员核销、权限隔离
- 硬门槛：写操作未经确认直接调 Service 层会被拒绝；跨角色越权返回 403

## 已知限制

1. 造型知识图谱当前覆盖常见犬种，长尾品种退化为「体型 + 毛质」匹配
2. 毛质评估为图像启发式实现，精度有限，定位是打通链路而非替代人工判断
3. 向量检索为进程内余弦计算，切片规模超过 50 万需替换独立向量库（接口已隔离）
4. 排期锁为数据库行锁，单实例语义；多实例部署需换 Redis 或 `GET_LOCK`
