## 一、项目简介

PawPilot（内部代号 PetGroom）是一套面向宠物洗护 / 寄养门店的一站式经营 SaaS，覆盖宠主自助预约、店员现场运营、店长经营分析三端，并在业务之上构建多 Agent 智能助手与可溯源的 RAG 知识底座。担任全栈开发，负责后端服务、多 Agent 编排、RAG 链路与前端页面，完整落地从需求、架构到测试交付的全流程，当前版本 V8.6.0。

## 二、技术栈

- **后端**：Python 3.13 / FastAPI / SQLAlchemy 2.x（async）/ aiomysql / Alembic / Pydantic v2 / MySQL 8
- **前端**：Vue 3 / Vite / TypeScript / Element Plus / Pinia / ECharts
- **AI 应用**：阿里云百炼 OpenAI 兼容接口（httpx 直连）/ 多 Agent 协作（路由调度 + 领域子 Agent）/ ReAct / LlamaIndex + Chroma / text-embedding-v4 / pypdf + python-docx
- **工程与质量**：JWT + RBAC / pytest（服务层覆盖率门槛 80%）/ CDP 无头浏览器 E2E / Alembic 迁移 / Gitee

## 三、核心职责与成果

### 3.1 多 Agent 编排设计

- **架构选型**：自研多 Agent 协作架构，1 个路由调度 Agent 负责意图判定与任务分派，7 个领域子 Agent（健康问诊 / 饲养营养 / 行为训练 / 用品导购 / 宠物档案 / 门店业务 / 经营分析）各司其职，1 个合规风控 Agent 横切校验；**不引入 CrewAI / AutoGen 等多 Agent 框架**，避免角色自由协商导致流程不可预测。
- **统一执行内核**：9 个 Agent 共用同一个 ReAct 执行器与工具注册表，本质是「一套内核 + 九份领域配置」，子 Agent 只携带各自的领域提示词与工具子集，规则互不稀释；跨 Agent 协同由路由层按显式编排调度（健康判断先于营养建议，有依赖串行、无依赖并行），子 Agent 之间不直接对话。
- **三端差异收敛**：三个端共用同一套 Agent 定义，差异体现在可激活 Agent 与工具白名单（`ROLE_TOOL_PROFILE`：宠主 13 / 店员 11 / 店长 11，工具池 30 个）；健康问诊对宠主完整开放、店员仅预问诊辅助、店长只看风险报告，经营分析仅店长可见。
- **双层编排**：内层 ReAct 循环完成「意图识别 → 工具调用 → 观察结果」，外层显式状态图驱动预约、寄养等业务流转；状态合法性由后端状态迁移表唯一裁定，Agent 不得自行判定，业务状态零非法跃迁。
- **写操作隔离**：LLM 仅产出「意图 + 结构化参数」，落库统一经 Service 层（权限 → 状态机 → 事务 → `operation_log` 审计）；`WRITE_INTENTS` 从 `WRITE_TOOLS` 派生，新增写工具自动进入确认闸门；表单与对话共用同一方法与 `idempotent_key`，杜绝双入口行为分裂。
- **确定性动作规则优先**：页面跳转、设备开关等不交由模型改判，直接下发 `navigate` 事件，规避幻觉与误操作。
- **可用性保障**：模型两级回退（qwen3.7-max → glm-5.1）配合工具级 try/except 兜底，两者都不可用时降级到规则引擎；意图与工具入参按角色画像二次校验，越权调用直接退回规则结论。

### 3.2 RAG 知识底座

- **对话内检索，无独立搜索入口**：RAG 是全部 Agent 的统一知识底座，检索作为 Agent 工具（`search_knowledge`）在对话链路内按需触发；知识库管理页只做文档治理（上传 / 切块 / 任务 / 删除 / 重建），不设搜索页签——检索的价值是支撑回答，脱离回答单独搜文本拿不到结论。
- **知识分片**：按疾病 / 营养膳食 / 饲养管理 / 行为心理 / 用品商品 / 门店私有六类分片隔离，检索时按目标 Agent 限定分片范围，缩小候选集提升精度。
- **分层解耦**：能力层 `app/rag`（向量索引 / 文档解析切块）与编排层 `app/services`（业务权限、事务、任务状态）分离；替换向量库不影响业务代码，调整业务流程不影响索引实现。
- **入库流水线**：上传 → 校验（单文件 20MB、单次 5 个、SHA-256 内容去重）→ 解析（PDF / DOCX / TXT / Markdown，保留页码）→ 三策略切块（标题 / 段落 / 固定长度，块大小 100~4000、重叠小于块大小且 ≤1000）→ 异步写块并重建索引。
- **可溯源切块**：每块记录页码区间、段落区间、字符区间与来源标注（如「文件 · 第6-7段 · 小节」），回答附 `refs` 引用折叠面板，可精确回指原文，而非笼统摘要。
- **异步任务可靠**：asyncio 信号量限流（并发 2）加索引串行锁，任务四态（待处理 / 处理中 / 完成 / 失败）带进度与失败原因；进程重启自动重排未完成任务，前端 3 秒轮询。
- **索引新鲜度**：collection 元数据记 `entries` 并与 DB 条目数比对，不一致自动重建；上传块以 `TextNode` 直入避免二次切碎；召回阈值 rerank 0.45 / 向量 0.30 且全不达标时保底保留最高分。

## 四、量化成果

- 单测 106 项全绿，服务层覆盖率 **82.05%**（门槛 80%）；冒烟 261 项、浏览器 E2E 123 项全部通过。
- Agent 侧：**9 个 Agent（1 路由 + 7 领域 + 1 风控）**、统一执行内核、3 端激活组合（8/8/4）、30 个工具（13 个受控写）、45 条意图评测双 100%（规则法与模型法）。
- RAG 侧：6 类知识分片（疾病 / 营养 / 饲养 / 行为 / 用品 / 门店私有）、3 种切块策略、4 张知识表、4 级 embedding 兜底；知识条目 24 条 / 67 个切块，文档增删后索引自动同步。
- 交付版本 V8.6.0，单机进程部署，支持店长 / 店员 / 宠主三角色权限收敛。
